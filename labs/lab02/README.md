## 3. Детальний опис завдань і модулів

### 3.1. Завдання 1: ООП-система моделювання користувачів (`task1.py`)

Модуль реалізує архітектуру об'єктно-орієнтованого програмування для безпечного керування обліковими записами:

* **Клас `User`**:
  * Реалізує інкапсуляцію даних користувача (`username`, `email`, `role`, `active`).
  * Зберігає паролі в захищеному вигляді: використовується алгоритм гешування `hashlib.pbkdf2_hmac("sha256", ...)` із 100 000 ітерацій та генерацією унікальної випадкової солі через `os.urandom(16)`.
  * Перевірка пароля здійснюється за допомогою `hmac.compare_digest()` для запобігання атакам за часом (Timing Attacks). Пароль ніколи не зберігається у відкритому вигляді.
  * Валідація `email` виконується через пару декораторів `@property` та `@email.setter` за допомогою регулярного виразу (локальна частина від 3 до 64 символів, починається з літери, обов'язкова наявність `@` та доменної зони з крапкою). При некоректному форматі піднімається виняток `ValueError`.
* **Клас `Admin(User)`**:
  * Демонструє принцип наслідування (*Is-A*).
  * Розширює базовий функціонал користувача списком системних прав і дозволів (`permissions`), надаючи методи `grant_permission`, `revoke_permission` та `has_permission`.
* **Клас `Session`**:
  * Фіксує IP-адресу клієнта, час входу та останньої активності виключно в часовому поясі UTC (`datetime.now(timezone.utc)`).
  * Метод `is_active(timeout_sec)` порівнює інтервал неактивності за допомогою `timedelta`.
* **Клас `AuditRecord` та `AuditLog`**:
  * Окремий запис аудиту реалізовано як `@dataclass` із полями `timestamp`, `username`, `action`.
  * Журнал зберігає послідовність дій (`login_success`, `login_failure`, `logout`) без запису конфіденційних паролів.
* **Клас `UserAccount`**:
  * Демонструє принцип композиції (*Has-A*), об'єднуючи об'єкти `User`, `Session` та `AuditLog`.
  * Методи `login()` та `logout()` керують життєвим циклом сеансу та реєструють події в журналі аудиту.
  * Метод `is_authenticated()` перевіряє факт наявності та валідності відкритої сесії за таймаутом.
  * Реалізовано магічні методи `__getitem__` та `__setitem__` для надання інтерфейсу словника (наприклад, `account["user"]`) із суворою перевіркою типів та забороною доступу до гешу й солі пароля.

**Команда для запуску Завдання 1:**
```powershell

```

### 3.2. Завдання 2: CLI-сканер PII-витоків (`task2.py`)

Утиліта для пошуку незахищених персональних даних (Personally Identifiable Information) у текстових файлах та журналах:

* **Рекурсивний обхід каталогів (`pathlib.Path`)**: Метод `Path.rglob("*")` здійснює рекурсивний пошук файлів у каталозі з автоматичним фільтруванням прихованих файлів.
* **Пошук за регулярними виразами (`re`)**:
  * **Email-адреси:** `\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b`
  * **Номери банківських карток:** `\b(?:\d{4}[-\s]?){3}\d{4}\b`
  * **Номери телефонів:** міжнародні та національні шаблони форматування.
  * **IPv4-адреси:** перевірка коректності кожного з чотирьох октетів у межах від 0 до 255.
* **Підрахунок кількості знахідок (`collections.Counter`)**: Швидка агрегація кількості знайдених вразливих записів за відповідними типами.
* **Безпечне маскування (`mask_pii`)**: Приховування конфіденційної частини записів перед виведенням на екран або записом (наприклад, `4000-****-****-0002` чи `c****1@example.test`).
* **Обробка винятків (`try...except`)**: 
  * Зчитування вхідних файлів захищене блоком `try...except (OSError, UnicodeError)` для уникнення збоїв при обробці бінарних чи заблокованих файлів.
  * Збереження вихідного JSON-звіту захищене блоком `try...except OSError` для коректного виведення сповіщення в разі помилок запису на диск.

**Команда для запуску Завдання 2:**
```powershell
python -m labs.lab02.main analyze --scan-dir labs/lab02/data/data_v13 --out-json labs/lab02/data/pii_scan_summary.json
```

### 3.3. Головний модуль диспетчеризації CLI (`main.py`)

Модуль надає єдину точку входу за допомогою стандартної бібліотеки `argparse`, реалізуючи підкоманди `demo` та `analyze`.

#### Опис параметрів підкоманди `analyze`:
| Параметр / Прапорець | Тип | За замовчуванням | Опис |
| :--- | :--- | :--- | :--- |
| `--scan-dir` | `str` | `labs/lab02/data/data_v13` | Шлях до директорії, файли якої необхідно перевірити |
| `--patterns` | `str` | `all` | Фільтр категорій пошуку (`all`, `cards`, `emails`, `phones`, `ips`) |
| `--no-mask` | прапорець | `True` (маскування увімкнене) | Якщо передано, вимикає маскування PII у виведенні результатів |
| `--out-json` | `str` | `labs/lab02/data/pii_scan_summary.json` | Шлях для експорту структурованого звіту у форматі JSON |

#### Приклади використання різних параметрів CLI:
* **Базовий запуск аналізу:**
  ```powershell
  python -m labs.lab02.main analyze
  ```
* **Сканування тільки банківських карток із вимкненим маскуванням:**
  ```powershell
  python -m labs.lab02.main analyze --scan-dir labs/lab02/data/data_v13 --patterns cards --no-mask
  ```
* **Пошук лише електронних адрес зі збереженням звіту за власним шляхом:**
  ```powershell
  python -m labs.lab02.main analyze --patterns emails --out-json labs/lab02/data/emails_report.json
  ```

## 4. Обробка помилок та поведінка утиліти

* **Відсутність каталогу:** Якщо шлях `--scan-dir` не існує або не є директорією, викликається виняток `FileNotFoundError` зі зрозумілим описом.
* **Помилки читання файлів:** Якщо окремий файл недоступний для читання (бінарний формат, відсутність дозволів), спрацьовує перехоплення `(OSError, UnicodeError)` — генерується повідомлення рівня `logger.warning`, а сканування інших файлів продовжується в штатному режимі.
* **Помилки запису звіту:** При неможливості створити каталог або записати файл за шляхом `--out-json` виняток перехоплюється через `OSError`, а помилка фіксується у журналі як `logger.error`.
* **Некоректні аргументи CLI:** Якщо користувач вказує неіснуючий ключ або невалідне значення аргументу `--patterns`, бібліотека `argparse` автоматично виводить повідомлення про помилку та інструкцію використання із кодом завершення 2.

## 5. Контроль якості та форматування коду (Ruff)

Для перевірки синтаксису, сортування імпортів (isort) та форматування за стандартами PEP 8 використовуються наступні команди:

```powershell
# Перевірка на помилки та відповідність стандартам
ruff check

# Перевірка форматування без внесення змін
ruff format --check

# Автоматичне виправлення зауважень та форматування файлів
ruff check --fix
ruff format
```
